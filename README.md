# 展覧会ビジョンボード・テンプレート

コンセプトから具体的な行動までをつなぐ、展覧会準備用の作業シートです。
ブラウザで `index.html` を開くだけで使えます（インストールや特別な準備は不要です）。

---

## 1. フォルダの中身（SE初心者向け解説）

```
vision-board-template/
├── index.html      ← ページの「骨組み」。文字や見た目はほぼ書いていません
├── css/
│   └── style.css   ← 「見た目」だけを担当（色・余白・文字サイズなど）
├── js/
│   ├── data.js     ← 「内容」だけを担当（実際の文言・リストの初期値）
│   └── app.js      ← 「動き」を担当（画面を組み立てる・保存する・印刷する）
└── README.md        ← このファイル
```

Web開発では、こうやって役割ごとにファイルを分けるのが基本です。
それぞれ英語の頭文字で **HTML / CSS / JS** と呼ばれます。

- **HTML** = 文章構造（見出し・段落・入力欄など、家でいう「骨組み」）
- **CSS**  = 見た目（色・レイアウト、家でいう「内装」）
- **JS(JavaScript)** = 動き（クリックしたら反応する、など。家でいう「電気・水道」）

1つの`.html`にすべて詰め込むと、修正のたびに長いファイルの中から該当箇所を
探すのが大変になります。分けておくと「見た目だけ直したい→style.cssを開く」
のように、目的のファイルだけ触ればよくなります。これが今回の一番大きな変更点です。

さらに `data.js` を `app.js` から分離しているのは、**来年別の展示で
このテンプレートを使い回すとき、data.js の中身（文言）だけ書き換えれば
よい**ようにするためです。app.js（仕組み側）は触らずに済みます。

## 2. 使い方

### そのまま使う
`index.html` をダブルクリックすればブラウザで開きます。それだけで動きます。

### ローカルサーバーで開く（任意・少し発展的）
一部のブラウザでは、ファイルを直接開く(`file://...`)と一部機能が制限される
ことがあります。気になる場合は、フォルダの中でターミナルを開いて以下を実行すると、
簡易サーバー経由で開けます。

```bash
# Python がインストールされている場合
python3 -m http.server 8000
# その後ブラウザで http://localhost:8000 を開く
```

## 3. 「確定／未確定」を切り替える機能について

各リストの項目の左に、緑色の「確定」または黄色の「未確定」ボタンがあります。
クリックするたびに切り替わります。文言はそのまま入力欄で書き換えられ、
「×」で削除、「＋ 項目を追加」で新しい項目を増やせます。

**仕組み（SE的な説明）：** 各項目は内部的に

```json
{ "text": "壁一面を使いたい", "status": "confirmed" }
```

のような小さなデータとして扱われています。`status` が `"confirmed"`（確定）か
`"undecided"`（未確定）かによってボタンの色と表示文字が変わります。ボタンを押すと
この `status` の値を書き換えて、画面を再描画しているだけです。

## 4. 保存の仕組みについて（重要）

このテンプレートは **localStorage** というブラウザ標準の仕組みで、入力した
内容をブラウザ自身に保存しています。サーバーには一切送信されません。

知っておいていただきたい制約：

- **保存されるのは「このブラウザ」「この端末」だけ**です。スマホとパソコンなど、
  別の端末・別のブラウザを使うとデータは引き継がれません。
- ブラウザの「閲覧履歴やデータを削除する」を実行すると、保存内容も消えます。
- Claudeのチャット画面に貼り付けてプレビューした場合は、Claude側のセキュリティ
  制限により保存が効かないことがあります。**ファイルをダウンロードして、実際の
  ブラウザ（Chrome・Safariなど）で `index.html` を開いてご利用ください。**

複数端末で共有したい・データを失いたくない、という場合は、後述の「6. Gitに
アップロードする」を使ってファイル自体をバックアップする方法をおすすめします
（入力内容そのものの同期には対応していません。あくまでコードのバックアップです）。

## 5. 印刷ボタンについて（前回動かなかった件の原因と対策）

前回チャット上のプレビュー内で印刷ボタンが動かなかったのは、Claudeのチャット画面が
セキュリティ上の理由で「ページ内モーダル（印刷ダイアログなど）」の表示を制限する
`iframe`（ページの中に埋め込まれた小さなページ）という仕組みの中でプレビューを
表示していたためです。コード自体の不具合ではありません。

**対策：** 今回のように `index.html` をダウンロードして、実際のブラウザで直接
開いていただくと、この制限がなくなるため印刷ボタンは正常に動作します。
万が一それでも反応しない場合は、キーボードショートカット `Ctrl+P`
（Macの場合は `⌘+P`）でも同じ印刷ダイアログを開けます（ボタンの下にもヒントを
表示しています）。印刷レイアウトは `style.css` の一番下、`@media print` という
部分で「印刷時だけ非表示にする要素」などを調整しています。

## 6. Gitにアップロードする（任意）

Git初心者向けに、最短の手順だけ載せておきます。

```bash
# 1. このフォルダに移動
cd vision-board-template

# 2. Gitの管理下に置く
git init

# 3. すべてのファイルを追加
git add .

# 4. 「これで1つの区切り」として記録する（コミット）
git commit -m "初回コミット: 展覧会ビジョンボードテンプレート"

# 5. GitHubなどに公開する場合（先にGitHub側でリポジトリを作成しておく）
git remote add origin <あなたのリポジトリのURL>
git branch -M main
git push -u origin main
```

GitHubにアップロードすると、「GitHub Pages」という無料の機能で
`index.html` をそのままWeb上に公開することもできます
（Settings → Pages から設定できます）。

## 7. カスタマイズしたいとき

- **文言を変えたい** → `js/data.js` を編集（`text:` の中身を書き換える）
- **色や余白を変えたい** → `css/style.css` を編集
- **項目の種類を増やしたい**（例: 新しいテキストエリアを追加）→
  `js/data.js` の `blocks` 配列に `{ type: "textarea", key: "...", label: "...", rows: 3 }`
  のようなオブジェクトを追加するだけで、`app.js` が自動的に描画します。

## 8. 内容についての注意

展示内容・コンセプト・6人の関係性・具体的な展示方法など、ユーザーが
決めていない事項はこのテンプレートに追加していません。既に記載されていた
内容はそのまま保持しています。

アップロードいただいた画像のうち「18. 成功の指標」の一部は元画像の解像度の
関係で判読できず、空欄またはアイコンで印を付けています。該当箇所は
`js/data.js` 内の `s18-items` を検索すると見つかります（`unclear: true` や
`flag:` が付いている項目です）。内容をご確認・加筆ください。
